# MCl₃(H₂O)₃ 6배위 계산 — 검토 요청

김동현 · 2026-09-30 · 실행 전 승인 요청

---

## 1. 왜 이걸 돌리려 하나

민이형이 지적한 것 그대로입니다.

> "DFT라 이게 맞긴 한데, 최종물질이 뭔지는 우리가 잘 입력 안 해주면 잘못 나올 수밖에 없음"

맞는 말입니다. DFT는 **우리가 후보로 넣어준 구조들 중에서만** 답을 고릅니다. 실제로 존재하는 화학종이 후보에 없으면 계산이 아무리 정확해도 답이 틀립니다.

**지금 우리 후보 목록의 구멍은 이겁니다.**

| 후보 | 배위수 |
|---|---|
| M(H₂O)₆²⁺ | 6 (팔면체) |
| MCl(H₂O)₅⁺ | 6 |
| MCl₂(H₂O)₄ | 6 |
| MCl₃(H₂O)⁻ | **4 (사면체)** ← 여기서 갑자기 떨어짐 |
| MCl₄²⁻ | 4 |

Cl이 2개에서 3개로 갈 때 배위수가 6에서 4로 **한 번에** 떨어집니다. 그런데 그 사이에 있을 법한 **MCl₃(H₂O)₃ (6배위)** 를 후보에 넣은 적이 없습니다.

그래서 지금 우리 결론인 *"Cl 3개째에서 사면체로 꺾인다"* 가

- 계산으로 **찾아낸** 것인지
- 후보를 그렇게 짜서 **나올 수밖에 없던** 것인지

**구분이 안 됩니다.** 이 계산이 그 구분을 만듭니다.

## 2. 결과가 어느 쪽으로 나오든 쓸모가 있습니다

| 결과 | 의미 | 우리가 할 일 |
|---|---|---|
| **6배위가 더 안정** | 전환점이 지금보다 **오른쪽**에 있음 | 지도를 고쳐야 함. 발표 전에 알게 된 게 다행 |
| **4배위가 더 안정** | 기존 결론이 후보 선택의 결과가 아님 | 지적에 정면으로 답할 수 있음 |

지금은 이 질문에 **답이 없습니다.** 심사위원이 같은 걸 물으면 막힙니다.

## 3. 무엇을 돌리나

**6개 계산** = 금속 3종 × 이성질체 2종

- 금속: Ni(II), Co(II), Mn(II) — 전부 고스핀
- 이성질체:
  - **fac** (facial) — Cl 3개가 한 면에 모임, 서로 전부 cis
  - **mer** (meridional) — Cl 3개가 자오선에 늘어섬, 둘은 trans

어느 쪽이 안정한지 미리 알 수 없어서 둘 다 돌리고, **낮은 쪽**을 그 화학종의 에너지로 씁니다.

계산 조건은 **기존 15종과 완전히 동일**합니다. 그래야 에너지를 직접 비교할 수 있습니다.

```
구조 최적화 : r2SCAN-3c / CPCM(SMD water)
진동수      : NumFreq, 298.15 K 와 333.15 K
엔진        : ORCA 6.1.1
```

## 4. 비용

기존 계산 실측 시간에서 추정했습니다. 새 구조는 **13원자**로, 기존 `MCl₂(H₂O)₄`(15원자, opt 1681초 + freq 2123초)보다 작습니다.

| | |
|---|---|
| 잡 개수 | 6개 (동시 실행) |
| 잡당 코어 | **1개** (총 6코어 / 노드 128스레드) |
| 잡당 예상 | 약 1시간 (최악 3시간) |
| **전체 벽시계** | **약 1~3시간** |
| 메모리 | 잡당 6 GB 상한 (ORCA `%maxcore`) |
| 디스크 | 수 GB |

노드는 128스레드 / 251 GB라 **6코어는 전체의 5%** 입니다. 다른 분들 작업에 지장 없습니다.
제출 전 `squeue`로 다른 사용자 작업을 확인하겠습니다.

## 5. 안전장치

밤새 돌려도 터지지 않게 다음을 걸어뒀습니다.

- **단계별 `.done` 플래그** — 재제출해도 끝난 단계는 건너뜀
- **재시도 사다리** — 수렴 실패 시 `SlowConv` → `NormalOpt` → `KDIIS` 순으로 자동 재시도
- **`timeout`** — 무한루프 차단 (xtb 30분 / opt 6시간 / freq 10시간)
- **`--requeue`** — 노드 문제로 죽으면 Slurm이 자동 재투입
- **`--mem` 미사용** — 이 노드는 `RealMemory=1`이라 `--mem`을 넣으면 제출 자체가 거부됨
- **별도 출력 폴더(`mcl3_oh/`)** — 이미 끝난 계산을 건드리지 않음
- **제출 전 자체검사** — 인풋 18개 무결성, 배위수 6 확인, 원자 겹침 확인, 줄끝 문자 확인.
  하나라도 이상하면 **서버에 올라가기 전에** 죽습니다.

## 6. 실행 방법

```bash
# 1) 인풋 생성 (로컬에서 해도 됨)
python build_mcl3_oh.py

# 2) 서버로 올리고 제출
scp -r mcl3_oh anode0:~/dft_ni_complexes/
ssh anode0
cd ~/dft_ni_complexes/mcl3_oh
squeue            # 다른 사람 작업 먼저 확인
sbatch run_mcl3.sh

# 3) 상태 확인
squeue -u $USER
tail -f STATUS.txt
```

## 7. 되돌리는 법

```bash
scancel -n mcl3                          # 실행 중인 잡 취소
rm -rf ~/dft_ni_complexes/mcl3_oh        # 전부 삭제
```

**기존 계산 결과에는 영향이 없습니다.** 별도 폴더이고 기존 파일을 읽지도 쓰지도 않습니다.
